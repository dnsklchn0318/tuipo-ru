# tuipo-ru

Локальная проверка русского и английского текста в выбранном терминальном
приложении. Название исполняемого файла остаётся `tuipo`.

**Публикация и автоматическое включение заблокированы аудитом.** Остаются известные
уязвимости зависимостей и невозможность надёжно распознать секреты в raw-TUI.
Не используйте эту версию для конфиденциальных промптов и не включайте автообёртку.
Подробности: [SECURITY.md](../SECURITY.md), [отчёт аудита](PUBLICATION_AUDIT.md).

Проект основан на [Tuipo автора ARahim3](https://github.com/ARahim3/tuipo).
Исходные лицензии MIT OR Apache-2.0 и авторство сохранены. Форк добавляет русский
словарь и дополнительные сочетания для подтверждаемого исправления слов.

## Сборка и ручной запуск

Из каталога репозитория в Terminal.app:

```sh
cargo build --locked --release
./target/release/tuipo -- codex
```

Проверяется только эта сессия выбранного приложения. Другие окна, команды и
клавиатурные события macOS программе недоступны. Постоянный сервис не устанавливается.

Введите `превет world `, дождитесь подчёркивания и переместите курсор внутрь
`превет` или сразу после последней буквы. Ctrl+N открывает варианты и выбирает
следующий; Ctrl+P выбирает предыдущий по кругу. Enter подтверждает замену,
Escape закрывает меню без изменений. Первый вариант не обязательно правильный.
Отправка сообщения после исправления — отдельное действие.

## Управление

```sh
./target/release/tuipo on
./target/release/tuipo status
./target/release/tuipo off
```

`on` разрешает проверку при следующем явном запуске приложения. Он не создаёт
демон, shell hooks или автозагрузку. `off` переводит работающие обёртки в передачу
байтов без буфера проверки и анализа экрана; новые запуски обходят Tuipo полностью.
После отключения нужно выполнить `on` и перезапустить Codex для возобновления
проверки. `status` показывает режим и блокировку автоматической интеграции.

Для полного обхода Tuipo с самого начала:

```sh
TUIPO_PRIVATE=1 ./target/release/tuipo -- codex
```

В этом режиме Tuipo заменяет себя выбранным приложением. Собственная сеть, история
и логи Codex остаются под управлением Codex. При признаках SSH-сессии или вложенной
обёртки также используется прямой запуск без анализа ввода.

## Настройки и ограничения

Конфиг: `$XDG_CONFIG_HOME/tuipo/config.toml`, иначе `~/.config/tuipo/config.toml`.
Оба языка включены по умолчанию. Полный пример находится в [английском README](../README.md#configuration).
Пользовательский словарь исключений содержит по одному слову на строку.
`highlight_only` отключает исправления, но продолжает обработку текста.

Проверка работает локально. В debug записываются только технические метаданные.
Tuipo не сохраняет историю промптов, но само приложение и терминал могут это делать.
Стандартный парольный ввод с выключенным echo обходит проверку. Скрытые поля raw-TUI,
API-ключи и секреты, введённые как обычный текст, надёжно распознать нельзя.

Составные Unicode-графемы и широкие символы внутри ввода отключают исправления.
Меню может не открыться при тесном или неоднозначном расположении. Визуальная
проверка Terminal.app и интерактивного Codex этим аудитом не подтверждена.
План ручных проверок: [RUSSIAN.md](RUSSIAN.md).

## Удаление

Выполните `tuipo off`, завершите выбранное приложение и запускайте `codex` напрямую.
В ходе аудита пользовательские shell-файлы не изменяются: удалять интеграцию не
требуется. Если вы сами установили бинарник через Cargo, удалите его командой
`cargo uninstall tuipo`. Удаление выбранных вами логов и каталога конфигурации —
отдельное ручное действие. Старые hooks следует удалять только по их точному
содержимому, не затрагивая остальные настройки оболочки.
